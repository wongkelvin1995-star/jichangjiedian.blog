## 2. 收录范围：40 个可索引，34 个 noindex，为什么

总指令第 20 节要求：**“如果 34 家品牌中某些资料明显不足，保留其完整目录条目，但不要强行生成 34 篇内容薄弱的可索引文章。在资料充分后逐步开放详情页。”** 本站的做法：

| 类别 | 页面数 | 是否可索引 | 说明 |
| --- | ---: | :---: | --- |
| 首页 | 1 | 是 | |
| 功能与数据页：`/airports/`、`/regions/`、`/routes/`、`/time-tests/`、`/test-records/`、`/plans/`、`/testing-methodology/`、`/sources/` | 8 | 是 | |
| 站点说明页：`/about/`、`/affiliate-disclosure/`、`/privacy/` | 3 | 是 | 信任信号，不追求排名 |
| 地区页 `/regions/<地区>/` | 7 | 是 | 香港、日本、新加坡、中国台湾、美国、韩国、欧洲，正文由真实的品牌覆盖数据生成 |
| 品牌页：灵动云、飞猫云 | 2 | 是 | 总指令点名灵动云；飞猫云的页面存档资料较完整，也开放 |
| 灵动云新加坡测速专题 | 1 | 是 | 旗舰报告 |
| 研究文章：列表 + 13 篇 | 14 | 是 | 总指令第 22 节的第 1–8、11、13–15 篇，以及站长追加的《按使用场景选机场》 |
| 教程：列表 + 3 篇 | 4 | 是 | 第 9、10、12 篇 |
| 其余 32 个品牌页 | 32 | **noindex,follow** | “资料卡”：保留完整目录条目与对应链接，但不提交收录 |
| `/search/`、`/404.html` | 2 | **noindex** | 站内搜索结果与错误页没有独立的收录价值 |

**为什么 32 个品牌页是 noindex？** 这些品牌目前只有页面存档给出的套餐价格、地区和线路说明，缺少本站独有的内容（本站实测、原图证据、整理核对）。如果把它们都做成可索引页面，会得到 32 篇结构雷同、信息增量很低的页面——这正是总指令和搜索引擎质量指南都要避免的。其中不少品牌的身份还没有确认（神行云、云界云、无忧、环球云……），把未确认的信息做成可索引页面更不合适；`validate:brands` 会拒绝把身份未确认的品牌设为可索引。

**这是一个有代价的取舍，请知情：** 总指令第 21 节的品牌关键词（暮光加速线路、微风网络套餐、大佬云测速……）因此**没有对应的可索引落地页**，只能由 `/airports/` 目录页（列出全部 34 个品牌名）和站内搜索承接。要为某个品牌争取品牌词流量，需要先为它积累本站独有的内容（带日期的实测、原图、整理核对），再把 `detailPage` 改为 `'open'`（见 DEPLOYMENT.md 第 10 节）。

**noindex 的写法。** 用 `<meta name="robots" content="noindex,follow">`，**不用 robots.txt 的 Disallow**——如果被 Disallow 挡住，搜索引擎就读不到页面里的 noindex 指令。`robots.txt` 是 `Allow: /` 加 sitemap 地址。

## 6. 内链策略

- **导航与页脚**：8 项主导航（总指令指定）+ 页脚的信任类页面（关于、合作推广声明、隐私政策、资料来源、测试方法）。
- **中心—辐射**：`/articles/`、`/guides/`、`/regions/`、`/airports/` 是枢纽页；每篇文章在正文里自然引用 2–5 个相关页面（相关文章、地区页、测试档案、方法页），并在末尾有“相关阅读”。没有为凑数量而堆链接。
- **数据页互联**：地区页 ↔ 品牌目录 ↔ 套餐对比 ↔ 线路知识；灵动云专题 ↔ 测试档案 ↔ 分时段测试。
- **规范形式**：站内链接一律写成根路径加结尾斜杠，不写 `/index.html`，不带域名，避免产生重复 URL。
- **推广链接**：只出现在品牌目录与品牌页，`rel="sponsored nofollow noopener noreferrer"`，不传递链接权重，也不进入搜索索引、CSV 和 JSON-LD。

入链统计（39 个可索引页面，含导航与页脚）：最少 6、中位数 19、最多 72。只数 `<main>` 正文内的链接时，最低的是隐私政策（1）、合作推广声明（2）、首页（3）、关于（3）——它们本来就靠导航与页脚被发现，不需要正文内链。所有文章与教程页的正文入链 ≥ 3。

- **篇幅**：按“H1 + 正文，含标点和数字、不含空格”（与 Word / WPS 的“字数（不计空格）”一致）为 1513–1812 字；只数汉字为 1060–1355。总指令说“主专题参考 1500 至 2000 中文字，技术必要时可增减”，两种口径下都在合理范围内，较短的几篇属于“技术必要时”的情形，我没有为凑字数而注水。
- **不照搬上传资料**：`scripts/check-originality.ts` 把正文与你上传的 71 个 TXT/MD 文件（约 18.5 万字）做 12 字片段比对。15 篇文章与资料的重合度最高 1.7%（《IEPL、IPLC与BGP》，主要是线路名称等专有名词），最长连续重合 33 字；其余多数为 0%。通过标准：重合 ≤ 8%，且没有连续超过 36 字的重合。
- **不照搬其他博客**：这一点无法由脚本证明。我没有查阅或改写其他机场推荐网站的文章；文章内容由测试方法、网络基础知识和本站自己的数据组织而成。
- **没有虚构的评分、星级、用户评价、测速或价格**：`validate:content` 扫描全站的评分与评价字样；`validate:evidence` 守护数据规则。

### 8.2 这些数字的局限（请务必看）

- **这是实验室数据，不是 PageSpeed Insights，也不是真实用户数据（CrUX）。** 它在本地服务器上用模拟节流测得，没有真实网络延迟、没有 HTTP/2/3、没有 CDN 的缓存行为。线上数字会不同，几乎一定更差一些。满分不等于“Core Web Vitals 达标”——后者要看真实用户的 75 分位数据，新站要有足够流量才会出现。
- **INP 没有直接测量**，Lighthouse 不报告它。我用 Playwright 在 CPU 4 倍降速下做了近似：开场动画结束后，点地区约 130ms、地图筛选约 30ms、搜索输入约 30–50ms、套餐排序约 100–140ms、预算筛选约 90–120ms，全部在 200ms 以内；其中**我们自己的脚本**每次只占 2–28ms，其余是浏览器的样式、布局与绘制。开场动画（航线逐条绘制，约 2.6 秒）期间点击会更慢（约 150–180ms）。这是实验室近似，不是 INP。
- **首页 HTML 较大但压缩后很小**：首页 209KB（gzip 27.6KB），套餐页 395KB（gzip 26.5KB）。这是因为地区面板与 300 条报价是服务端直接输出的（关闭 JS 也能读），换来的是对搜索引擎和无 JS 访客友好；体积由压缩吸收。首页只加载 7 KB JS（压缩后 3 KB）、37 KB CSS（压缩后 9 KB），共 7 个请求；站内搜索索引（32 KB，压缩后 7.8 KB）在用户聚焦搜索框时才加载。
- **图片**：站内只有一张大图——灵动云的数据整理图（PNG 2.3 MB），页面只加载 WebP 版本，PNG 仅作为“查看原图”链接，不随页面加载。

### 8.3 为了性能做过的修正（审计中发现的）

- 套餐页的筛选表单原来在脚本就绪后才显示，造成布局位移（CLS）。现在表单在 HTML 里就占好位置（控件先禁用），脚本就绪后才启用。
- 首页地图 9 个区域点的“呼吸光环”原本同时无限循环，会让浏览器每一帧重绘整张 SVG 地图，在 4 倍降速下把点击响应拖慢 60–90ms。现在只有“当前选中”的光环在桌面端呼吸，手机端不循环动画；`prefers-reduced-motion` 下全部关闭。
- 套餐页的筛选脚本原先在比较器和过滤循环里反复读取 DOM 的 `dataset`（很慢），现在初始化时一次性解析成普通对象，排序结果缓存，`hidden` 只在状态变化时才写。

## 9. 安全与隐私响应头（`public/_headers`）

| 头 | 值 |

## 10. 审计中发现并修复的问题

| 发现 | 修复 |
| --- | --- |
| 手机上品牌页横向溢出（页面宽度被宽表格里绝对定位的子元素撑开） | 表格容器设为定位祖先，并让按钮可换行 |
| 手机上香港与台湾圆点只隔约 7px，点击区域重叠，点台湾会选中香港 | 点击时按“离哪个圆点中心最近”判定，并加大点击热区 |

| 窄屏上可横向滚动的表格无法用键盘操作 | 表格实际可滚动时才加 `tabindex`、`role="region"` 和唯一的名称 |
| 搜索框与页眉出现重复的 landmark | 为表单加上区分名称 |
| 点击目标小于 24×24（WCAG 2.2 AA 的 2.5.8） | 页脚、面包屑、目录等链接统一最小高度 |
| 套餐页筛选表单造成 CLS | 见 8.3 |
| 地图呼吸动画拖慢点击响应 | 见 8.3 |
