## 5. 需要你知道的风险与取舍

- **新站 + 推广站的收录难度。** 搜索引擎对“主要靠推广链接盈利的新站”相当谨慎。本站的应对是：原创研究文章、公开的测试方法、明确的证据等级、对冲突和未核验的如实披露，并且只让有实质内容的 39 个页面进入 sitemap。**这些不能保证收录，更不能保证排名**——站内、文档和脚本里都没有这样的承诺，请不要在对外宣传里使用这样的说法。
- **内容的可信度取决于你后续补充的证据。** 目前本站没有任何一条“已核验”的测试记录。真正能让站点与同类网站拉开差距的，是你持续提供带日期、带原图的测试，而不是页面数量。
- **资料不新鲜的风险。** 页面存档没有抓取日期，不少“页面自述日期”是 2026-09/10 的评测站说法；机场价格和节点变化很快。站内一律写“页面标注某日”，不写“本站于某日核验”。资料更新后请同步修改 `DATA_UPDATED`（见 DEPLOYMENT.md 第 10 节）。
- **合规与托管条款。** 本站内容涉及跨境网络服务，不同地区的法律规定和不同托管平台的服务条款不同。站内已有合规提示（“使用任何网络服务请遵守所在地区适用的法律法规”）。上线前请自行确认你的托管平台条款和适用法律——我不是律师，也没有核查这些。
- **推广链接与 `noreferrer`。** 按总指令，推广链接带 `rel="sponsored nofollow noopener noreferrer"`。`noreferrer` 会让对方看不到来源页面；绝大多数联盟靠链接里的推广码计量，不受影响，但个别联盟若依赖 Referer，需要向服务商确认。
- **字数口径。** 总指令要求文章“约 1500–2000 字”。15 篇的实际篇幅按“H1 + 正文，含标点和数字、不含空格”计为 1513–1812；若只数汉字则是 1060–1355。两种口径我都在验收报告里给出了，没有只挑好看的数字。

## 6. 上线前建议顺序

1. 设置环境变量（至少 `PUBLIC_CONTACT_EMAIL`），`npm ci && npm run verify && npm run test`，确认全部通过。
2. 在你自己的电脑上运行 `npm run check:external -- --affiliate-only`，处理失效的推广入口（向服务商确认新地址，**不要自行改写**）。
3. 部署，确认首页、`/sitemap.xml`、`/robots.txt`、IndexNow 密钥文件都能从线上打开，响应头生效。
4. 按 DEPLOYMENT.md 第 8 节完成 Bing 与 Google 的验证、提交 sitemap。
5. 线上运行一次 Lighthouse / PageSpeed Insights，并用手机真机看首页地图和套餐页。
6. 补齐灵动云三张原图（1.1），再逐步积累带日期的测试记录。
7. IndexNow 首次提交（`--all --submit`），之后只提交有变化的 URL。
